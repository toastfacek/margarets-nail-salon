### 0.3 Rules that apply to every WP

1. **No file outside your WP's "owns" list may be edited.** If you need a change elsewhere, stop and report it.
2. **No external network requests**, no downloaded art or audio. Every asset is generated in code.
3. **No per-frame allocations in hot paths** (`update`, `step`, `splat*`, pointer-move handlers, shader uniform updates). Use module-level or instance scratch objects. No `new`, no `.clone()`, no array/object literals, no closures created per frame, no template strings per frame.
4. **No text for the player.** Icons, colour, motion and sound only. Numerals are allowed (star count). `title=` attributes are fine for accessibility but must not be the only signal.
5. **Every `localStorage` access goes through `src/core/Storage.js`** (try/catch, quota handling).
6. **Never call `console.log` in a per-frame path.** Remove the existing per-mesh setup logs you touch.
7. Keep the perf-harness hooks alive (section 0.5).
8. Each WP ends with: `npm run build` clean, the harness run pasted into the hand-off note, and a list of any budget line it missed.
9. No Poki SDK, no ad code, no analytics in this pass.

### Starting tier

1. `?tier=` wins.
2. Else the tier saved by a previous session (`storage.get('q.tier')`).
3. Else heuristics: renderer string (via `WEBGL_debug_renderer_info`, wrapped in try/catch) containing `SwiftShader`, `llvmpipe`, `Mali-4`, `Mali-T6`, `PowerVR SGX`, `Adreno (TM) 3`, `Intel(R) HD Graphics 400` -> low. `navigator.hardwareConcurrency <= 4` or `navigator.deviceMemory <= 4` -> medium. Otherwise high.
4. No half-float render-target support (`EXT_color_buffer_float` and `EXT_color_buffer_half_float` both missing) -> low with `noFlow = true` (paint splats only, no velocity sim).

### Auto-downgrade rule

- `FrameLoop` feeds every frame delta to `Quality.sample(dt)`. Ignore samples when `document.hidden`, when dt > 250 ms, and during the first 2 s after load or after any tier change.
- Keep a ring buffer of 90 samples (preallocated `Float32Array`). Every 30 samples compute the median.
- **Down:** median > 28 ms (under about 35 fps) on two consecutive checks -> step down one rung. Rungs in order: high -> medium -> low(1.0) -> low(0.85) -> low(0.7) -> low(0.6). At the last rung, stop.
- **Up:** allowed once per session only: median < 11 ms for 10 s continuously on medium -> high. Never up from low within a session (avoids oscillation); the saved tier is retried one rung higher on the next visit if the session median stayed under 14 ms.
- At most 4 changes per session. Persist the final tier on `visibilitychange`.
- A tier change must not hitch more than one frame: reallocation of sim targets preserves the dye by blit; shader variants for the next tier down are compiled at idle time after load (`renderer.compileAsync`).
- Emit `quality:change`.

### WP1: Brush and fluid performance core (+ app spine)

**Goal.** Paint goes from the fluid sim straight to the nail in a shader with zero CPU readback, the sim sleeps when nothing moves, layers composite instead of overwriting, and quality scales itself.

**Depends on:** nothing. **Parallel with:** WP2.

**Owns.** `src/main.js`, `src/scene/NailScene.js`, `src/scene/HandModel.js`, `src/tools/PolishBrush3D/*` (delete `WetPaintMaterial.js` and `BristlePaintApplicator.js`), new `src/scene/NailMaterial.js`, new `src/core/FrameLoop.js`, `Quality.js`, `GameEvents.js`, `Storage.js`, new folder `src/features/` (with a `.gitkeep`).

**Approach.** Do it in this order; the game must run after every step.

1. **Spine.** Create `GameEvents` (tiny emitter, no deps), `Storage` (try/catch wrapper, JSON, returns fallback on any error, `set` returns false on quota), `FrameLoop` (the only rAF; ordered callbacks; computes dt once; `invalidate()`; when `quality.settings.renderOnDemand` and not `?perf=1`, callbacks marked `render` are skipped unless invalidated, with a forced render at least every 250 ms as a safety net), `Quality` (section 2). In `main.js`: set `this.__ready = false` in the constructor; replace `startAnimationLoop()` and `NailScene.animate()`'s self-scheduling with `app.loop.add(...)` in this order: input/brush update (10), features (50), `scene.render()` (90). `NailScene` exposes `update(dt)` and `render()` instead of owning rAF. `updateCameraAnimation()` uses the real dt, not `1/60`. Add the feature glob (0.4). Make the Done button `emit('ui:done')` (keep `showCelebration()` as the fallback when `listenerCount('ui:done') === 0`), gallery `emit('ui:gallery')` with the same fallback pattern. Remove the unused `FileTool` import. Activate the polish tool for real at startup (today the polish panel shows but `currentTool` is `'shape'` and the brush is not active). While any tool other than `shape` is active set `controls.enableRotate = false` so painting never orbits the camera; restore on `shape`.

2. **Renderer by tier.** `NailScene.init()` takes `quality.settings`: `antialias`, `powerPreference: 'high-performance'`, `setPixelRatio(settings.pixelRatio)`, `shadowMap.enabled = false` (the key light stops casting; WP3 adds the baked contact shadow). React to `quality:change` by calling `setPixelRatio` + `setSize`. Remove `console.log`s in load paths.

3. **`NailMaterial.js` v1 (layer compositing).** `createNailMaterial(settings)` returns a `THREE.ShaderMaterial` (not `onBeforeCompile` on Physical: we want the cheap path and full control). Replaces both the `MeshPhysicalMaterial` and the overlay mesh in `HandModel.setupNailForHand()`; delete the overlay mesh. Uniforms: `uPaintMap`, `uHasPaint`, `uDecoMap`, `uHasDeco`, `uBaseColor` (natural nail `#FFDDD2`), `uUnderColor`/`uUnderAmount` (legacy `setPolishColor`), `uWet`, `uFinish` (int), `uHighlight`, `uRevealPulse`, `uLightDir`, `uEnvMap`/`uHasEnv` (unused until WP3). Fragment outline for v1:

   ```glsl
   vec4 paint = uHasPaint ? texture2D(uPaintMap, vUv) : vec4(0.0);   // rgb straight, a = coverage
   vec4 deco  = uHasDeco  ? texture2D(uDecoMap,  vUv) : vec4(0.0);   // canvas, straight alpha
   vec3 albedo = mix(uBaseColor, uUnderColor, uUnderAmount);
   albedo = mix(albedo, paint.rgb, smoothstep(0.02, 0.6, paint.a));
   albedo = mix(albedo, deco.rgb, deco.a);                           // stickers and drawing sit ON TOP of polish
   // v1 lighting: hemisphere + one Lambert key + one Blinn highlight + Schlick rim. WP3 replaces this block.
   gl_FragColor = vec4(lit, 1.0);
   #include <tonemapping_fragment>
   #include <colorspace_fragment>
   ```

   Put the lighting in a clearly marked `// --- LIGHTING (WP3 replaces) ---` block. Paint and deco are sampled with the same `vUv` the raycaster returns, `flipY = false` everywhere (matches today).

4. **Lazy per-nail resources in `HandModel`.** Deco canvas + `CanvasTexture` created on first `getDrawingContext()`/`getDrawingTexture()` at `settings.decoCanvasRes` (on low: 512 with `ctx.setTransform(0.5,0,0,0.5,0,0)` so tools that hardcode 1024 keep working; `clearDrawing()` must reset the transform, clear, then restore). `generateMipmaps = false`, `LinearFilter`. Baked paint target created on first paint: `WebGLRenderTarget(res, res, { type: UnsignedByteType, format: RGBAFormat, minFilter/magFilter: LinearFilter, depthBuffer: false, generateMipmaps: false })`. Compute `uvAspect` and the 32x32 `nailMask` once per nail (rasterise the UV triangles on CPU). Load only the left hand in `load()`; `ensureHandLoaded('right')` loads on demand and `switchHand` awaits it. Implement the new API in 0.6. Selection highlight becomes the `uHighlight` uniform (no `material.needsUpdate`, no `new Color`).

5. **`FluidSimulator` rewrite.** Signature `new FluidSimulator(renderer, { simRes, dyeRes, iterations, dyeType, noFlow })`. No module-level state, so WP9 can create a second instance.
   - Targets: velocity double FBO at `simRes` (`HalfFloatType`, `RGFormat` if it validates, else RGBA), pressure double + divergence at `simRes` (`HalfFloatType`, `RedFormat`/RGBA; not allocated when `iterations === 0`), dye double FBO at `dyeRes` (`dyeType`). All `depthBuffer: false`, `LinearFilter`, clamp. Replace `FloatType` everywhere.
   - One shared full-screen triangle geometry; all materials created once in the constructor; `depthTest: false`, `depthWrite: false`.
   - `renderPass()` saves and restores `renderer.getRenderTarget()`, `autoClear`, and scissor/viewport state. It never leaves a target bound.
   - **Splats without ping-pong:** `splatSegment(ax, ay, bx, by, radius, color, strength, aspect)` draws ONE small quad covering only the capsule's bounding box directly into `dye.read` with `CustomBlending` (`blendSrc: SrcAlphaFactor`, `blendDst: OneMinusSrcAlphaFactor`, `blendEquationAlpha: MaxEquation`, `blendSrcAlpha: OneFactor`, `blendDstAlpha: OneFactor`) and `renderer.autoClear = false`. The fragment computes distance to the segment in aspect-corrected UV space, a soft edge (`smoothstep`), and a bristle-streak profile across the stroke (`0.88 + 0.12 * sin(perp * uStreakFreq + uSeed)`) written into alpha so WP3 can turn it into wet ridges. `splatVelocity(...)` does the same into `velocity.read` with additive blending. One segment per frame covers any pointer speed, so there is no stamp loop.
   - `step(dt)`: advect velocity -> advect dye -> (if `iterations > 0`: divergence, clear pressure, N Jacobi, gradient subtract). Advect uses `texelSize`-correct back-tracing. Returns nothing.
   - **Sleep:** the sim tracks `energy` on the CPU: `energy = max(energy * velocityDissipation, splatSpeed)` per step. `isAwake()` is `energy > 1e-3 || framesSinceSplat < 30`. `PolishBrush3D` steps only while awake. Idle cost is zero passes.
   - `loadDye(texture | null)` (blit into `dye.read`, or clear), `saveDye(target)` (blit `dye.read` into a nail's baked target), `fill(color, alpha)`, `clear()`, `getTexture()`, `setQuality({...})` (reallocate, preserving dye by blit), `blit(srcTexture, dstTarget, uvTransform?)` (used by WP9), `dispose()`. Delete `copyToCanvas()`, `debugFill()`, the unused `copy` material if not needed by blit.
   - `noFlow` mode: only splats, `step()` is a no-op.

6. **`PolishBrush3D` rewiring.**
   - One sim, bound to the active nail. On `nail:select`, hand switch, or deactivate: `fluidSim.saveDye(handModel.getPaintTarget(prev))`, `handModel.setPaintTexture(prev, bakedTarget.texture)`, then `fluidSim.loadDye(next baked texture or null)` and `handModel.setPaintTexture(next, fluidSim.getTexture())`. After every dye swap inside `step()`, refresh the active nail's `uPaintMap` value (a pointer assignment). This fixes the "same paint on every finger" bug.
   - `update(dt)` (takes dt from `FrameLoop`, not `performance.now()`): input -> one `splatSegment` + `splatVelocity` when painting and the UV moved more than half a dye texel -> `if (fluidSim.isAwake()) fluidSim.step(dt)` -> bristles -> `app.loop.invalidate()` when anything changed. Remove the `copyToCanvas` block, `paintApplicator`, `wetOverlay`, `getNailCanvas()`, `playPaintSound()`.
   - Emit `brush:strokeStart`, `brush:stroke` (reused payload: UV speed in UV units/s, pressure, u, v, world position), `brush:strokeEnd`. Keep `onPaintStart`/`onPaintEnd`/`onCoverageChange` properties for compatibility.

   - `BrushInputHandler.getBrushTransform()`: no clones; write into a reused result object and reused vectors. Fix `tipOffset.clone()` and `toCamera` allocations.

Cap `updatePhysics()` at `physicsSubstepsMax` steps per frame and drop any remaining accumulator (no spiral). Replace the per-bristle BVH raycast in `handleCollision()` with collision against the tangent plane at the input handler's hit point and normal (pass them in); on high, refine with 8 evenly spaced raycasts. Contacts written into a preallocated pool (`contactCount` + fixed array of reusable objects); no `clone()`. Skip `update()` entirely (physics and matrices) when the pointer has not moved, pressure is 0 and joints are at rest (energy threshold). `MeshStandardMaterial` on bristles -> `MeshLambertMaterial` with emissive tint.

### WP3: Gorgeous polish, light and salon

**Goal.** Make the nail the most beautiful object on Poki: layered wet-to-cured polish with ring-light reflections, glitter and chrome, on a warm salon set with depth, inside the frame budget.

**Depends on:** WP1. **Parallel with:** WP4, WP5.

**Owns.** `src/scene/NailMaterial.js`, `src/scene/NailScene.js`, `src/scene/HandModel.js`, new `src/scene/SalonEnvironment.js`, `src/scene/Backdrop.js`, `src/scene/ContactShadow.js`, `src/scene/SkinMaterial.js`.

**Approach.**

1. **`SalonEnvironment.js`: environment map built in code.** Build a tiny throwaway `THREE.Scene` of emissive `MeshBasicMaterial` shapes (values above 1 for HDR): a big **ring light** (a `RingGeometry`, bright warm white, placed up and slightly toward camera: this is the signature highlight in every nail video), a large overhead softbox rectangle, a tall warm window strip on one side, a pink neon bar on the other, a soft gradient dome (inverted sphere with a vertical gradient via vertex colours: warm cream top, rose mid, deep plum floor). Render once with `THREE.CubeCamera` into `WebGLCubeRenderTarget(envCubeRes, { type: HalfFloatType or UnsignedByteType, generateMipmaps: true, minFilter: LinearMipmapLinearFilter })`. Expose `envCube.texture` for the nail shader (sampled with `textureLod(uEnvMap, R, lod)`, roughness -> lod; not physically exact prefiltering, visually right for polish, one fetch). On high and medium also run `PMREMGenerator.fromScene(envScene, 0.04)` once and assign `scene.environment` so skin, gems and the brush cap pick up the room; `scene.environmentIntensity` about 0.6. Dispose the generator and the env scene geometry afterwards. `setDim(x)` scales an intensity uniform for the reveal. Total one-time cost under 80 ms; do it before `compileAsync`.

2. **`NailMaterial.js` v2: the hero shader.** Replace the WP1 lighting block. Keep it ONE shader with tier `#define`s; target about 60 fragment-shader lines of real work. Outline:

   ```glsl
   // layers
   vec4 paint = ...; vec4 deco = ...;
   float cov = smoothstep(0.02, 0.6, paint.a);
   // natural nail under everything: soft pink, paler lunula near the cuticle (v small), free-edge whitening near the tip
   vec3 nailBase = naturalNail(vUv);
   // pooled-pigment rim: slightly darker where coverage changes fast
   float rim = clamp(fwidth(paint.a) * uRimK, 0.0, 1.0);
   vec3 pigment = paint.rgb * (1.0 - 0.18 * rim);
   vec3 albedo = mix(nailBase, pigment, cov);
   albedo = mix(albedo, deco.rgb, deco.a);

   // normal: geometric normal + wet relief from the streaks stored in paint.a
   vec3 N = normalize(vNormal);
   #ifdef WET_NORMAL_TAPS      // high: 4 taps
     vec2 g = vec2(a(uv+dx)-a(uv-dx), a(uv+dy)-a(uv-dy));
   #elif defined(WET_NORMAL_DERIV)  // medium: free derivatives
     vec2 g = vec2(dFdx(paint.a), dFdy(paint.a));
   #endif
   N = normalize(N + (g.x * vTangent + g.y * vBitangent) * uWet * uReliefK);

   vec3 V = normalize(vViewPos); vec3 R = reflect(-V, N);
   float NdV = clamp(dot(N, V), 0.0, 1.0);
   float F = 0.04 + 0.96 * pow(1.0 - NdV, 5.0);

   // base layer per finish
   //  glossy : diffuse albedo
   //  matte  : diffuse albedo, soft sheen at grazing angles, clearcoat nearly off
   //  shimmer: diffuse + micro-flakes
   //  chrome : no diffuse; coloured mirror = env(R, lod 1.0) * mix(vec3(1), pigment, 0.75)
   //  holo   : shimmer + cosine-palette hue driven by NdV and flake id (high only)
   // glitter: hash a UV cell -> random tilt nf; sparkle = pow(max(dot(reflect(-V, normalize(N + nf*0.35)), L), 0.), 48.) gated by a hash threshold
   //   GLITTER_2 = two cell scales, GLITTER_1 = one, GLITTER_CHEAP = threshold on hash(cell) * NdL only

   // top coat (every finish except matte): this is the wet-to-cured story
   float coatLod = mix(uCuredLod /*0.6 crisp hard gloss*/, 0.0 /*liquid mirror*/, uWet);
   vec3 coat = textureLod(uEnvMap, R, coatLod).rgb * F * mix(1.0, 1.35, uWet);
   // wet polish also gets a slow liquid wobble on N (one sin of vUv, amplitude * uWet) and a thicker dark rim
   vec3 col = base * (hemi + key * max(dot(N, L), 0.0)) + flakes + coat;
   col *= cuticleAO(vUv);                 // procedural darkening toward the skin folds
   col += uHighlight * selectionGlow + revealSweep(vUv, uRevealPulse);
   ```

   Finish parameters live in one `FINISHES` table exported from `NailMaterial.js` (metalness-like mix, flake density and scale, coat strength, cured lod). `HandModel.setFinish()` only writes uniforms; no `material.needsUpdate`. The vertex shader derives `vTangent`/`vBitangent` from the UV axes (the nail UVs are a planar projection, so tangent = local x, bitangent = local y, transformed by `normalMatrix`). Curing is just `uWet` going 1 -> 0 (WP4 drives it): highlights sharpen from a soft liquid blob into a crisp ring-light reflection. That transition is the satisfying moment; tune it by eye.

3. **Skin (`SkinMaterial.js`).** Take the GLB skin `MeshStandardMaterial`, set `side: FrontSide` if the mesh has no holes (check visually), roughness about 0.55, and add via `onBeforeCompile` a 4-line warm rim/subsurface tint (`diffuseColor.rgb += uSkinGlow * pow(1.0 - NdV, 3.0)`). Low tier: `MeshLambertMaterial` with the same colour and the rim added as emissive. `setSkinTone(color)` for WP6's clients. The nail mesh's old dark-red GLB material is no longer used.

4. **Lights.** Replace the six lights in `NailScene.setupLighting()` with `HemisphereLight` (cream sky, rose ground) + one warm `DirectionalLight` key aligned with the env ring light (+ one cool rim directional on high). Export the key direction to the nail shader's `uLightDir`. `setDim(x)` lerps intensities for the reveal.

5. **Contact shadow (`ContactShadow.js`).** The hand is static, so bake once per hand: render the hand with a flat black `MeshBasicMaterial` override from an orthographic camera looking up from under the desk into a `contactShadowRes` target, blur with a separable 9-tap shader (2 passes high, 1 medium), display on a desk-level plane as a multiply/alpha texture. Re-bake on `switchHand`. Low: a canvas radial-gradient blob stretched under the hand, no render pass. Zero per-frame cost on every tier.

6. **Backdrop (`Backdrop.js`).** One full-screen triangle drawn first (`depthTest: false`, `renderOrder: -1000`, `frustumCulled: false`): warm vertical gradient, a blurred shelf line with soft bottle silhouettes (sums of smoothstep rounded boxes with hash colours), 8 to 12 bokeh discs with slow drift and parallax from the camera azimuth, vignette, `uDim`. Plus a desk: a large plane with a canvas-generated 512 texture (soft towel weave: two sine weaves + noise, pastel) that fades into the backdrop with distance. Low tier: render the backdrop shader once into a 512x288 target and use it as `scene.background` (re-render only when `uDim` changes); medium and high animate. When the backdrop animates, the loop renders continuously on that tier (that is why `renderOnDemand` is off on high; on medium throttle the bokeh drift to invalidate at 20 Hz).

7. **Tier wiring.** `createNailMaterial(settings)` picks defines; on `quality:change` swap to the pre-compiled variant. Variants for the current tier and the next one down are compiled at load.

**Keep compatible.** All of 0.6. `uPaintMap`/`uDecoMap` semantics from WP1 (straight alpha; paint alpha = coverage with streak modulation). `NailScene.focusOnPosition`, `zoomOut`, `getRaycaster`, `setCameraLocked` unchanged. `scene.background` may change type.

**Acceptance.**
- Visible: at the zoomed-in view a painted glossy nail shows a recognisable ring-light reflection that slides as the camera moves. Wet polish looks liquid; when `setWetness` goes to 0 the highlight snaps crisp. Shimmer twinkles when the camera moves and does not crawl when it is still. Chrome reads as coloured metal. Matte has no mirror highlight. Bare nails look like healthy natural nails, not grey plastic. The hand sits on a surface with a soft shadow; the background has depth and warmth and no hard horizon line. Take the five-finish screenshot set (same camera, hot pink) and attach it.
- Measured (harness `tier=low`): scene-only <= 30 ms; slices in 1.2 respected (measure by toggling each element off). `tier=high` scene-only <= 69 ms. Texture memory within 1.3 (list every target and its bytes in the hand-off). Main-pass draw calls <= 25 (<= 16 low). No shadow-map pass in `renderer.info`.
- No `material.needsUpdate = true` and no new `THREE.Color` in any per-frame or per-selection path.

**Budget share.** Backdrop 3, hand 10, nails 6, desk + shadow 3 (low tier ms).

### WP5: Sound design (Web Audio only)

**Goal.** A soft, wet, musical soundscape synthesised in code that makes painting feel good with eyes closed.

**Depends on:** WP1 (events), WP2 (howler gone). **Parallel with:** WP3, WP4.

**Owns.** `src/audio/*`, new `src/features/audio.feature.js`.

4. **One-shots**, all pitched to a C major pentatonic set so nothing ever sounds wrong: `uiTap(index)` (marimba-like: sine + fast decay + a click), `bottlePop` (cork: noise burst through a resonant lowpass sweep), `stickerPop`, `gemClink` (two detuned high sines, long decay), `coverageRise(coverage)` (a note that climbs the scale as the meter fills), `covered` (three-note arpeggio + shimmer), `dryerLoop` start/stop (filtered noise with slow LFO), `cureTing` (glass: 3 inharmonic partials), `starDing(n)` (ascending), `shutter` (two noise clicks) + `flashWhoosh`, `confettiPop`, `clientYay` (a wordless happy "woo": two formant bandpasses over a sawtooth with an upward-then-down pitch glide, 350 ms; test three variants and keep the cutest), `doorBell` ("ding-dong" for the next client), `swish` for camera moves.
5. **Ambient bed (optional, on by default at low volume):** a generative music-box loop: pentatonic notes on a soft sine/triangle voice with a feedback delay, about 70 bpm, scheduled 200 ms ahead with a 100 ms `setInterval` lookahead (not per frame). Ducks under the reveal.
6. **Wiring.** `audio.feature.js` subscribes to the event catalogue: `brush:*`, `nail:coverage`, `nail:covered`, `nail:cured`, `deco:placed`, `tool:change`, `nail:select`, `roundStart` (door bell), `reveal:start/flash/done`, `ui:mute`. **Keep compatible.** Singleton export `soundManager`. Missing or blocked `AudioContext` must never throw.

**Acceptance.**
- Audible: stroke sound follows speed continuously with no clicks or machine-gun retriggers; lifting the brush gives a plip; every UI sound is in key; mute silences everything within 50 ms and persists across reloads; no sound before the first user gesture and no console autoplay warnings.
- Measured: no `createBuffer`/`createOscillator` per frame during a stroke (one voice for the whole stroke); voices capped at 12; main-thread audio work <= 0.2 ms per frame; harness numbers unchanged.

**Budget share.** <= 0.2 ms.

**Approach.**
1. **Modes.** `app.mode = 'round' | 'free'`. Round mode is the default. In round mode `main.js` adds `body.mode-round`, which hides the sandbox chrome (finger number bar, layer tabs, lock/undo/clear, header) via `styles/game.css`; the elements stay in the DOM (`[data-tool="polish"]` must still exist for the harness). A small door icon toggles free mode (today's sandbox, unchanged). OrbitControls are disabled in round mode; the camera is fully scripted (`focusOnPosition` per nail, gentle 2-degree idle sway on high/medium).
2. **`ClientRequests.js`.** Pure data + a seeded generator. A request = `{ skinTone, fingers: [...], color, finish, sticker? }`. Ramp: client 1 = one nail (index), plain glossy, hot pink; client 2 = three nails; client 3+ = five nails; finishes unlock in order glossy -> shimmer -> chrome -> matte; stickers from client 4. Eight starting colours from the existing palette. Six skin tones. All invented, no names.
3. **`RoundManager.js`** state machine: `arrive` (hand slides in from the bottom over 600 ms with a `doorBell`, skin tone applied, previous paint cleared, request bubble pops) -> `paint` (`roundStart` emitted; when a nail fires `nail:covered` and the pointer is up, auto-advance the camera to the next requested finger after 500 ms; skipped under `?perf=1`) -> `ready` (the Done button, a big pulsing nail-polish heart icon, appears as soon as any nail has >= 30% coverage: the kid decides when it is finished) -> on `ui:done`: compute stars, emit `reveal:request`; wait for `reveal:done`, or continue immediately if `listenerCount('reveal:request') === 0` (hard timeout 8 s) -> emit `roundEnd` -> `leave` (hand slides out) -> next `arrive`. `roundStart`/`roundEnd` are the only hook points the later Poki SDK step needs; put a comment block there saying so.
4. **`Scoring.js`: never fail.** `stars = 1 + (avgCoverage >= 0.6) + (avgCoverage >= 0.85 && colorMatch)`, minimum 1 always. `colorMatch` is generous: hue within 40 degrees of the request for the majority colour used on the requested nails (track the colours used per nail in `PolishBrush3D` stroke events on the CPU; no readback). A sticker request adds a bonus sparkle, never a penalty. No timer anywhere.
5. **`RequestBubble.js`.** A DOM thought bubble (CSS shapes) anchored top-left in landscape, top-centre in portrait, containing a **picture**: a small `<canvas>` drawing of a nail silhouette filled with the requested colour, a finish cue (diagonal gloss streak, glitter dots, chrome gradient, or flat for matte), the sticker emoji if any, and N small nail pips for how many nails. Each pip fills as that nail reaches 90%. `pointer-events: none`.
6. **`StarMeter.js`.** Three star outlines near the bubble that fill live with average coverage (so progress is always visible); the final count is confirmed in the reveal.
7. **Start mid-stroke.** First ever session (`storage.get('seen.intro')` false): after load the camera is already zoomed on the index nail, `polishBrush3D.autoStroke()` has painted a wet stripe over about 40% of the nail in the request colour, and the brush rests at the end of that stripe. No title, no menu, no button.
8. **`GhostFinger.js`.** An inline-SVG cartoon hand pointer (drawn in code) in a `pointer-events: none` layer. It loops: press at the end of the stripe -> drag along the nail toward the tip -> lift -> fade, 1.6 s loop. Positions come from projecting nail UV points to screen each loop start (`Vector3.project(camera)`), so it is correct in every layout. Disappears on the first `brush:strokeStart`; returns after 6 s idle while coverage < 20%, and once more to tap the Done heart when all requested nails are covered. Sets `seen.intro` after the first completed round. Also used once to point at the dryer the first time it appears. Disabled under `?perf=1`.
9. **Colour choice in round mode.** A bottom tray of 8 round bottle buttons (CSS-drawn bottles tinted per colour); the requested colour's bottle bounces gently. Choosing any other colour is allowed. Finish follows the bottle (a small glitter/chrome badge on the bottle icon).

**Keep compatible.** Section 0.5 in full. Free mode keeps every existing tool reachable. `main.js` keeps the feature glob and all `app.*` services.

**Acceptance.**
- Visible: cold load to "a kid is painting" needs zero taps and under 4 s on the harness; a non-reader can complete round 1 (test: play with all text hidden; there should be none to hide). Three rounds in a row work; nail counts go 1, 3, 5; stars are always 1 to 3; clearing storage replays the intro; second session skips the auto-stroke but still opens on a client.
- Measured: harness painting numbers unchanged vs WP4 (+0.5 ms max); DOM writes only on state change (no per-frame style writes except the ghost finger's CSS animation, which must be a compositor-only `transform` animation); `roundStart`/`roundEnd` fire exactly once per round (log count in the hand-off).

**Budget share.** <= 0.5 ms.

### WP7: The Slay reveal and the polaroid wall

**Goal.** Pressing Done triggers a 4.5-second show (lights down, camera sweep, glints, flash, confetti, squeal) and drops a photo onto a wall that persists on the device.

**Depends on:** WP3, WP4 (`Sparkles`), events from WP1. **Parallel with:** WP6.

**Owns.** New `src/reveal/RevealDirector.js`, `Confetti.js`, `PolaroidCamera.js`, `PolaroidWall.js`, new `src/features/reveal.feature.js`, new `styles/reveal.css`.

**Approach.**
1. **Trigger.** Listen for `reveal:request` (from WP6). If WP6 is not merged yet, also listen for `ui:done` directly when `listenerCount('reveal:request')` has no emitter (feature flag `app.mode === undefined`), so this WP is testable alone.
2. **Timeline** (`RevealDirector.play({ stars, hand, fingers })`, driven by `app.loop`, skippable by tap after 1 s, emits `reveal:start` at 0):
   - 0.0 s: `body.revealing` hides all UI (CSS opacity transition), brush hidden, input locked, all nails `setWetness(.., 0)` (instant hard gloss), music ducks.
   - 0.0 to 0.6 s: lights down: `backdrop.setDim(0.25)`, `scene.setDim(0.45)`; the environment stays bright so the nails keep their reflections and pop out of the dark.
   - 0.3 to 2.8 s: camera sweep along a Catmull-Rom path (`THREE.CatmullRomCurve3`, points computed from the nail world positions: low on the pinky side, across the knuckles, up to a 3/4 hero view of the whole hand). As the camera passes each nail: `setRevealPulse` runs 0 -> 1 (a diagonal sparkle sweep in the shader), one `Sparkles.burst`, one ascending `starDing`.
   - 2.2 to 3.2 s: finger wiggle. The hand is skinned: find finger bones by traversing `SkinnedMesh.skeleton.bones` and add a small phase-shifted sine rotation; if bone names cannot be mapped reliably, wiggle the whole hand group by 3 degrees instead. Restore exact rest pose afterwards.
   - 2.8 s: **photo.** `PolaroidCamera.capture()` then `reveal:flash`: a full-screen white DOM div, opacity 1 -> 0 in 250 ms, plus shutter sound.
   - 2.9 to 4.5 s: `Confetti.burst()`, stars pop in one by one (DOM, CSS scale-bounce, 1 to 3), `clientYay`, lights ease back up.
   - 4.5 s: the polaroid develops (CSS filter from white to image) and drops into a small stack in the corner; `reveal:done`.
3. **`Confetti.js`.** One instanced quad mesh, `settings.confetti` pieces, fully GPU-animated: attributes `aSeed`, `aVel`, `aColor`; the vertex shader does ballistic motion + flutter rotation from `uTime`; CPU writes nothing per frame. Hidden (no draw call) when idle. Camera-space so it works for any camera position.
4. **`PolaroidCamera.js`.** Render the scene (UI excluded by nature) with a dedicated camera framing the hand into a 384x384 `WebGLRenderTarget`, one `readRenderTargetPixels` into a preallocated `Uint8Array` (one-off readback is fine here; it never runs during painting), flip rows into a 2D canvas, compose a polaroid frame (white border, slight paper tint, the star count as drawn stars, a tiny heart) and export `toDataURL('image/jpeg', 0.8)` at 256 px (about 15 to 20 KB).
5. **`PolaroidWall.js`.** Store up to 20 photos under one key via `app.storage` (`{ v: 1, items: [{ t, stars, img }] }`); on quota failure drop the oldest and retry once, then give up silently. Takes over `ui:gallery`: fills `#gallery-grid` inside the existing `#gallery-modal` with photos pinned at small random rotations on a cork/washi-tape wall drawn in CSS; newest first; tap a photo to enlarge. Empty state is a picture (dotted polaroid outline + camera icon), not text. No share, no download, no links.

**Keep compatible.** Does not edit `main.js`, `index.html` or `styles/main.css` (hook only through events and the existing modal elements). Camera and controls state are restored exactly after the reveal. `NailScene` methods used: `setDim` (WP3), camera object.

**Acceptance.**
- Visible: the full sequence plays in 4.5 s +- 0.3, can be skipped, and always ends with UI restored and input unlocked (test: spam taps during the reveal, switch tabs mid-reveal, resize mid-reveal). A photo appears on the wall and survives a reload. The 21st photo evicts the oldest. With storage blocked, the reveal still completes and the wall shows the session's photos from memory.
- Measured: reveal frame time <= scene + 6 ms on harness low; no shader compile during the reveal (pre-warm confetti and flash at load); the capture hitch is a single frame <= 60 ms on harness; stored payload <= 450 KB for 20 photos.

**Budget share.** Transient <= 6 ms; 0 when idle.

### WP9 (stretch): Swirl bowl water marble

**Goal.** Drop colours into a bowl of water, swirl them with a finger, and dunk the nail to print the marble onto it: the thumbnail feature nobody else on the portal has.

**Depends on:** WP1 (`FluidSimulator` is instance-safe and has `blit`), WP3 (env map), WP4 (`Sparkles`). **Parallel with:** WP8.

**Owns.** New `src/bowl/SwirlBowl.js`, `BowlMaterial.js`, `BowlInput.js`, new `src/features/swirlBowl.feature.js`, new `styles/bowl.css`.

**Approach.**
1. **Entry.** A bowl icon button injected by the feature (free mode always; round mode only when a request has `finish: 'marble'`, which this feature registers with `ClientRequests` through an exported `registerRequestType` if WP6 exposes it; otherwise free mode only). Opening emits `bowl:open`, pauses the brush (`polishBrush3D.deactivate()`), and moves the camera to a top-down view of the bowl beside the hand.
2. **Bowl.** `LatheGeometry` ceramic bowl (Lambert + env) and a water disc with `BowlMaterial`: samples the bowl sim's dye texture; normal from the dye luminance gradient (2 extra taps on high/medium, none on low) for an oily relief; Fresnel env reflection of the ring light; a soft caustic ring at the rim.
3. **Sim.** A second `FluidSimulator` instance created on first open and disposed on close: `simRes`/`dyeRes` from the tier but dye capped at 384, `velocityDissipation` 0.985 (water keeps swirling, unlike polish at 0.85), `pressureIterations` from the tier but at least 4 while the bowl is open (swirls need projection; on low drop the main render scale one extra rung while the bowl is open to pay for it). Only one sim ever steps: the brush sim is asleep while the bowl is open.
4. **Interaction.** Tap a bottle -> a drop falls (small sphere + plop sound via `bowl:drop`) and lands as a `splatSegment` disc with radial outward `splatVelocity`, so successive drops form concentric rings exactly like real water marbling. Drag in the water = a toothpick: velocity-only splats along the drag (no dye), which pulls the rings into feathers and hearts. Max 12 drops, then the oldest colours just get pushed around.
5. **Dunk.** Press the dunk button (nail-into-water icon): the active finger's camera/hand does a short dip animation (hand group translate + rotate, 700 ms), then `fluidSim.blit(bowlDyeTexture, handModel.getPaintTarget(hand, finger), uvTransform)` prints the pattern under the nail's footprint in the bowl onto the nail's paint target with alpha 1 (full coverage), `setWetness(1)`, coverage map filled, `nail:covered`, `Sparkles.burst`, `bowl:dunk`. The printed region is cleared from the bowl dye (a soft hole), as in the real technique. Then the camera returns and the brush sim reloads the nail (`loadDye`).
6. **Sleep and cleanup.** The bowl sim sleeps by the same energy rule. Closing disposes its targets (texture budget is only charged while open).

**Keep compatible.** No edits outside owned files. Brush behaviour identical after closing the bowl.

**Acceptance.**
- Visible: three drops make three clean concentric rings; a drag makes feathered marble; the dunked nail shows the same pattern that was under it, glossy and wet; doing it on a second nail gives a different crop; closing the bowl returns to normal painting with previous nails intact.
- Measured: bowl open + swirling <= scene + 8 ms on harness low; texture memory stays within the tier cap while open; all bowl targets freed on close (`renderer.info.memory.textures` returns to the pre-open value).

**Budget share.** <= 8 ms while open (replaces the 6 ms brush-sim slice), 0 when closed.

## 5. Risks and mitigations

1. **WP1 rewrites the heart of the game in one package.** Mitigation: the eight ordered steps each leave the game running; commit per step; the v1 nail shader is deliberately plain so correctness (layers, per-nail paint, state restore) is reviewed before beauty arrives in WP3.
2. **SwiftShader is a proxy, not a Chromebook, and the custom nail shader must beat `MeshPhysicalMaterial` on looks while costing less.** Mitigation: fill-rate-driven tiers plus the dynamic resolution ladder give a guaranteed escape hatch; budget slices are measured by toggling elements; the five-finish screenshot set is a hard acceptance gate; get one real low-end Chromebook measurement before WP6 starts.
3. **Parallel WPs drift from the shared contracts (events, `HandModel` API, settings keys), or two of them need `main.js`.** Mitigation: contracts are frozen in sections 0.4 to 0.6 and section 2; integration is by events and feature files only; any contract change is a plan change that comes back to me before code is written.

Smaller risks: planar nail UVs stretch at strongly curved nail edges (aspect-corrected splats hide most of it; a per-nail unwrap is out of scope); emoji stickers render differently per platform (acceptable now, replace with code-drawn stickers later); half-float render targets missing on very old devices (handled by `noFlow` low tier); the finger wiggle depends on bone names in the GLB (fallback specified).
